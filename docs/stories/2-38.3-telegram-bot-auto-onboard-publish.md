# Story 2-38.3: Auto-onboard & auto-publish supplier Telegram bot

Status: in-progress

> Admin chỉ cần nhập bot username + số điện thoại Telegram trên dashboard, nhập OTP, hệ thống tự động login, khám phá catalog, tạo products, gộp group, tạo markup rule mặc định và publish all variants lên `@router_chainlensbot`.

## Story

As an **admin của 9Router**,  
I want **kết nối một supplier Telegram bot chỉ bằng vài bước trên web**  
so that **sản phẩm của supplier tự động xuất hiện trên shop `@router_chainlensbot` mà không cần chạy CLI relay hay config thủ công**.

## Bối cảnh và quyết định kiến trúc

### Hiện trạng
- `telegram_bot_scraper` adapter đã có `validate` / `fetchCatalog` / `purchaseProduct`.
- `relay` là script `scripts/telegram-relay.js` chạy riêng, cần CLI `--login` + file `relay-accounts.json`.
- Dashboard `/dashboard/suppliers` đã có CRUD source (2.30/2-38.1) nhưng chưa có wizard onboard tự động.
- `publishAllVariantsInGroup` đã có ở `markupEngine.js` (Story 2-38.2).
- `catalogSync` tạo external products với `isActive=0, isPublished=0`, cần admin publish trước khi lên shop.

### Quyết định kiến trúc

**QĐ1 — Web login flow qua relay.**
Relay sẽ expose `POST /login/start` (gửi phone code) và `POST /login/verify` (nhập OTP, trả session string). Server 9Router gọi relay như một dịch vụ MTProto, không tự giữ client connection trong Next.js route.

**QĐ2 — Request-scoped session trên `/relay`.**
`POST /relay` nhận thêm `session` trong body. Khi có `session`, relay tạo client tạm từ session đó thay vì accounts file, cho phép nhiều supplier source dùng nhiều Telegram account khác nhau. Security: yêu cầu `Authorization: Bearer` + relay chạy loopback.

**QĐ3 — Auto-discovery catalog từ supplier bot.**
Sau login, hệ thống gửi `/products` (hoặc `/start`) đến bot, thu thập messages và inline/reply buttons. Nếu gặp menu danh mục, tự động chọn nút chứa từ khoá như "Tất cả sản phẩm" / "sản phẩm". Sau đó parse các product buttons và product detail messages thành danh sách sản phẩm.

**QĐ4 — Parser mở rộng hỗ trợ button-based catalog.**
Nhiều bot hiển thị catalog dưới dạng inline buttons (`price|name`) thay vì danh sách số thứ tự. Parser mới nhận cả `buttonLabels` và `messages`, trích xuất `supplierProductId`, `name`, `priceVnd`, `stock`, `description`.

**QĐ5 — Auto-publish sau sync.**
Sau khi `catalogSync` upsert products, tìm tất cả `productGroupId` vừa tạo/cập nhật, tạo default markup rule 10% nếu chưa có rule nào, gọi `publishAllVariantsInGroup` cho từng group.

**QĐ6 — Security & lưu trữ.**
- OTP không lưu; session string được mã hoá trong `supplierSources.authEnc` (đã có `secretBox`).
- `TELEGRAM_API_ID` / `TELEGRAM_API_HASH` / `RELAY_AUTH_TOKEN` là env server, không xuống client.
- Phone number chỉ dùng để login, mask trong log/response.

## Acceptance Criteria

### AC1 — Wizard UI onboard
**Given** admin ở `/dashboard/suppliers`  
**When** click "Auto-onboard Telegram bot"  
**Then** modal wizard hiện 3 bước:
1. Nhập `botUsername`, `phone`, `vndPerCredit`.
2. OTP input (relay gửi code đến Telegram).
3. Review & confirm.

### AC2 — Start login
**Given** admin submit step 1  
**When** server gọi `POST /api/store/suppliers/onboard/telegram/start`  
**Then** relay gửi phone code đến số điện thoại  
**And** API trả `loginId` để bước tiếp theo.

### AC3 — Verify OTP
**Given** admin nhập OTP đúng  
**When** server gọi `POST /api/store/suppliers/onboard/telegram/verify`  
**Then** relay hoàn tất login, trả session  
**And** server tạo supplier source `telegram_bot_scraper` với auth chứa session.

### AC4 — Auto-discover catalog
**Given** source đã có session  
**When** verify thành công  
**Then** server tự động chạy discovery với bot supplier  
**And** parse product buttons/messages thành product list.

### AC5 — Auto-create markup rule
**Given** chưa có markup rule nào (hoặc không có rule cho supplier/global)  
**When** source được tạo  
**Then** hệ thống tạo global rule `markupPct=10, roundingRule=ceil`.

### AC6 — Auto-sync & auto-publish
**Given** discovery trả về products  
**When** `catalogSync` upsert xong  
**Then** hệ thống gọi `publishAllVariantsInGroup` cho từng product group  
**And** tất cả variants có `isActive=1, isPublished=1`.

### AC7 — Sản phẩm xuất hiện trên shop bot
**Given** publish thành công  
**When** `@router_chainlensbot` gọi `/products`  
**Then** danh sách sản phẩm từ supplier hiển thị (do `listActiveProducts` filter `isActive=1`).

### AC8 — Error handling
**Given** OTP sai, bot không trả catalog, hoặc parser không nhận diện được format  
**Then** wizard hiển thị lỗi rõ ràng, không tạo source/publish, không lưu session lỗi.

### AC9 — Idempotency & re-sync
**Given** source đã onboard  
**When** admin bấm "Re-sync & re-publish"  
**Then** discovery chạy lại, update products, publish new variants, không duplicate group.

### AC10 — Security
**Given** request không phải admin  
**Then** onboard endpoints trả 403.

## Notes / Risks

- **R1 — Multi-account relay:** mỗi supplier có thể cần số điện thoại khác nhau. Request-scoped session (QĐ2) giải quyết.
- **R2 — Parser format đa dạng:** các bot supplier khác nhau viết khác nhau. Parser MVP hỗ trợ format `tongmmobot`; các bot khác cần admin review/cập nhật interaction steps.
- **R3 — Telegram FLOOD_WAIT:** auto-discovery gửi nhiều request. Cần rate-limit và timeout hợp lý.
- **R4 — Security session string:** tương đương mật khẩu Telegram. Phải mã hoá trong DB và không log.

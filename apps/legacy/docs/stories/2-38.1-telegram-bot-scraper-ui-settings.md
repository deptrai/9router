# Story 2-38.1: Supplier Source CRUD UI — add/edit trên web, đầy đủ cấu hình `telegram_bot_scraper`

Status: done

> Story con của 2-38. Mục tiêu: đưa toàn bộ cấu hình scraper lên web UI, hỗ trợ tạo và chỉnh sửa nhiều supplier source từ dashboard admin.

## Story

As an **admin của 9Router**,  
I want **tạo và chỉnh sửa supplier source (đặc biệt `telegram_bot_scraper`) trực tiếp trên web UI**,  
so that **tôi có thể quản lý nhiều supplier bot khác nhau mà không cần gọi API thủ công hoặc sửa env**.

## Bối cảnh và quyết định kiến trúc

### Hiện trạng
- Backend CRUD supplier source đã có từ Story 2.30: `createSupplierSource`, `updateSupplierSource`, `listSupplierSources`, `getSupplierSourceById`, `deleteSupplierSource`.
- `telegram_bot_scraper` adapter (Story 2-38) đã validate đầy đủ `botUsername`, `vndPerCredit`, `relayUrl`, `relayToken`, `command`/`interactionSteps`, `collect`, `syncIntervalSec`.
- UI admin hiện tại (`/dashboard/suppliers`) chỉ **xem list + detail + sync/enable/disable**, chưa có form **add/edit**.
- Pattern modal tồn tại: `src/shared/components/EditConnectionModal.js` (LLM connection), dùng `Modal`, `Input`, `Button`, `Badge`.
- API không bao giờ trả auth plaintext; `maskSource` chỉ trả `hasAuth: boolean`.

### Quyết định kiến trúc

**QĐ1 — Thêm form add/edit supplier source trên `/dashboard/suppliers`.**
Tạo `AddSupplierSourceModal` + `EditSupplierSourceModal`, tận dụng `Modal`/`Input`/`Button` hiện có. Form gửi đến `POST /api/store/suppliers` và `PUT /api/store/suppliers/[id]`.

**QĐ2 — Form phân nhánh theo adapter type.**
- Generic fields: `name`, `adapterType`, `syncMode`, `syncIntervalSec`, `isActive`.
- Adapter-specific fields:
  - `supplier_api`: `apiUrl`, `apiKey`/`bearerToken`.
  - `channel_feed` / `polling_feed`: `feedUrl`, `apiKey`/`bearerToken`.
  - `webhook`: `webhookSecret`.
  - `telegram_bot_scraper`: `botUsername`, `vndPerCredit`, `relayUrl`, `relayToken`, `command` hoặc `interactionSteps` + `collect`.

**QĐ3 — `telegram_bot_scraper`: hỗ trợ cả single command và interactive steps trên UI.**
- Toggle giữa "Single command" (`command`) và "Interactive steps" (`interactionSteps`).
- Steps editor: thêm/xoá/sắp xếp step, mỗi step có `action` (`send`/`press`), `text`, `match` (`exact`/`contains`), `collect` (checkbox).
- `collect` editor: `timeoutMs` (100–60000), `idleMs` (10–10000), `maxMessages` (1–50), với validation `idleMs <= timeoutMs`.

**QĐ4 — Client validation mirror backend, nhưng source of truth vẫn là API.**
- UI có field-level validation cơ bản (required, range, regex) để giảm round-trip.
- Backend `adapter.validate()` vẫn là gate cuối; lỗi `createSupplierSource:` / `updateSupplierSource:` trả `422` và UI hiển thị `error`.
- Không tạo endpoint validate riêng trong story này — dùng response `422` từ create/update.

**QĐ5 — Credentials handling trên edit.**
- API không trả auth, nên form edit không pre-fill `relayToken`, `apiKey`, v.v.
- Nếu `hasAuth === true`, hiển thị nhãn "Đã lưu — nhập mới để thay đổi".
- Nếu người dùng để trống credential field, client không gửi key đó trong `patch.auth`; `updateSupplierSource` merge sẽ giữ giá trị cũ.
- Có nút/toggle "Clear credentials" để gửi `auth: null`.

**QĐ6 — Không đụng auto-checkout.**
Story này chỉ catalog sync. `deliveryMode` vẫn là `admin_fulfill` do adapter (`2-38 QĐ7`).

**QĐ7 — Multi-supplier ready.**
Backend đã hỗ trợ nhiều `supplierSources`. UI list refresh sau mỗi create/update. Không cần thay đổi DB schema.

## Acceptance Criteria

### AC1 — Admin mở form tạo supplier source

**Given** admin ở `/dashboard/suppliers`  
**When** click nút "Add supplier source"  
**Then** modal `AddSupplierSourceModal` hiện với dropdown chọn `adapterType` và các trường generic.

### AC2 — Form `telegram_bot_scraper` đầy đủ

**Given** chọn `adapterType = telegram_bot_scraper` trong modal  
**Then** UI hiển thị các trường:
- `name` (bắt buộc)
- `botUsername` (5-32 ký tự, bắt đầu bằng chữ, chỉ chữ/số/gạch dưới)
- `vndPerCredit` (số > 0)
- `syncIntervalSec` (>= 3600)
- `syncMode` (mặc định `polling`)
- `relayUrl` (bắt buộc, URL)
- `relayToken` (bắt buộc, password input)
- Toggle `command` / `interactionSteps`
- Nếu `command`: input text
- Nếu `interactionSteps`: steps editor + `collect` editor
- `isActive` toggle

### AC3 — Validate `telegram_bot_scraper` trên client và server

**Given** admin nhập config sai (`syncIntervalSec: 300`, `botUsername: "123"`, `match: "contains"` với target < 8 ký tự, `steps > 10`, `collect.idleMs > timeoutMs`)  
**When** submit  
**Then** UI báo lỗi tương ứng, không gọi API nếu client validation fail; nếu vượt qua client, API trả `422` với message từ `adapter.validate` và UI hiển thị rõ.

### AC4 — Tạo mới `telegram_bot_scraper` source

**Given** admin nhập đúng toàn bộ trường (hoặc `relayUrl`/`relayToken` lấy từ env nếu UI cho phép để trống)  
**When** submit  
**Then** `POST /api/store/suppliers` trả `201`, list refresh, source mới xuất hiện với `status`/`hasAuth`, auth được mã hóa trong DB.

### AC5 — Edit source và merge auth

**Given** admin mở `EditSupplierSourceModal` cho source đã có  
**When** chỉ đổi `vndPerCredit` hoặc `interactionSteps`, không nhập lại `relayToken`  
**Then** `PUT /api/store/suppliers/[id]` gửi `patch.auth` chỉ chứa field đã đổi; server merge với auth cũ; `relayToken` cũ không bị mất.

### AC6 — Edit source xoá credentials

**Given** admin chọn "Clear credentials" trong edit form  
**When** save  
**Then** client gửi `auth: null`; server set `authEnc = null`; source `hasAuth` trả về `false`.

### AC7 — Manual sync từ UI

**Given** source vừa tạo/sửa  
**When** admin nhấn "Test sync" trong modal hoặc hàng list  
**Then** gọi `POST /api/store/suppliers/[id]?action=sync` và hiển thị kết quả / lỗi (như `lastSyncError` đã có trong list).

### AC8 — Hỗ trợ các adapter còn lại

**Given** admin chọn `supplier_api`, `channel_feed`, `polling_feed`, hoặc `webhook`  
**Then** UI hiển thị đúng adapter-specific fields tương ứng (theo `validate()` của từng adapter) và submit thành công.

### AC9 — Regression

**Given** các test hiện có  
**When** chạy full suite  
**Then** không regression. Unit test mới pass cho form validation và modal render; integration test (tùy chọn) tạo/update source qua API/UI flow.

## Dev Notes

- `maskSource` không trả auth, nên edit form không thể pre-fill credential. UX chuẩn: nếu `hasAuth === true`, hiển thị placeholder hoặc text "Đã lưu"; khi user nhập, ghi đè.
- `updateSupplierSource` merge `patch.auth` với existing. Client chỉ cần gửi field người dùng đã thay đổi (kể cả credential). Để giữ credential cũ, đơn giản là không gửi key đó.
- `relayUrl`/`relayToken` có thể lấy từ env (`TELEGRAM_SCRAPER_RELAY_URL`, `TELEGRAM_SCRAPER_RELAY_TOKEN`) nếu admin để trống. Tuy nhiên UI nên khuyến khích nhập riêng để hỗ trợ nhiều supplier với nhiều relay.
- `command` vs `interactionSteps`: nếu toggle ở "Interactive", client gửi `interactionSteps` (mảng) + `collect`; `command` nên undefined. Nếu toggle ở "Single command", gửi `command`; `interactionSteps` undefined.
- `validateRelayRequest` trong `src/lib/telegram/relayCore.js` là single source of truth cho step/collect bounds. Nếu client validation muốn chi tiết, mirror các bounds từ đó (`MAX_STEPS=10`, `MIN_CONTAINS_LENGTH=8`, `COLLECT_BOUNDS`, `MAX_FLOW_TIMEOUT_MS=120000`).
- Không log credential trên client. `relayToken` nhập bằng `type="password"`; `botUsername` không phải secret.
